> 结论先行，事实可核验，不承诺做不到的事。

---

## 0. 一句话结论

你的需求里有一对**互相矛盾**的约束：

> 「**复刻**全部功能」 ＋ 「结果和原始项目**一模一样**」

只要"复刻"意味着**重新实现**，第二个约束必然被破坏——重写的代码不是原来的代码，算法实现、浮点归约顺序、边界条件处理只要有一丝差异，数值就会漂移。在医学场景，这种漂移不可接受。

**因此唯一同时满足两条约束的路线是：不重写，直接驱动原版引擎。** 让 Cytoscape 自己的 Java 代码去做计算，Skill 只负责"指挥"。

这条路线同时干净地满足了「不受 AI 影响」：**AI 只决定调用哪一条官方命令，绝不参与任何数值计算。** 结果由引擎产生，AI 换一个型号、换一次采样、甚至换一个厂商，输出都不变。

## 1. 事实核查（全部实测，附来源）

先把"这个项目到底是什么"钉死，因为网上大量二手中文资料是错的。

| 核查项 | 实测结果 | 来源 |
|---|---|---|
| 仓库定位 | **只是一个顶层 Maven 聚合工程**，内容为 `pom.xml` + `cy.sh` + 文档，体积 **889 KB** | GitHub API `/repos/cytoscape/cytoscape` |
| 真正的实现代码 | 不在本仓库。分布在 `cytoscape-api` / `-impl` / `-support` / `-gui-distribution` / `-app-developer` / `-parent` 六个同级仓库 + 20 多个 core app 仓库 | 仓库 README「Core Directory Structure」 |
| 语言与构建 | Java，Maven 3 + OSGi bundle，安装包由 **install4j（商业工具）** 生成 | README、`.travis.yml` |
| 许可证 | `cytoscape-impl` = **LGPL-2.1**；**顶层仓库没有 LICENSE 文件**（API 返回 `NONE`，网络资料常误传 MIT） | GitHub API `license` 字段 |
| Java 要求 | 3.10+ **必须 Java 17**。官方原话："Cytoscape requires Java 17"；3.10 起不再支持 Java 11 | `manual.cytoscape.org/en/latest/Launching_Cytoscape.html` |
| 本机 Java | `1.8.0_503`，major = 8 → **不满足**，且无 `javac` | 本机 `java -version` |
| 最新发行版 | **3.10.5**（2026-09-29 发布），另有 3.11.0 在 nightly 构建 | GitHub releases API |
| 自动化接口 | **CyREST**，默认 TCP **1234** 端口；`/v1/` 为函数接口，`/v1/commands/` 为命令接口；端口可用 `-R` 参数或 `rest.port` 属性改 | 官方手册 26 章 |
| 官方 MCP 服务器 | `cytoscape-desktop-mcp`，**BSD-3-Clause**，以 Cytoscape App 形式内嵌 MCP 服务器，走 Streamable HTTP，**官方文档明确支持 Claude Code / Codex CLI / Copilot** | 该仓库 README + `docs/AgentConfiguration.md` |
| 无头运行 | 官方 `headless-cmdline-parser-impl` **只支持 `-h` / `-v` / `-c <命令文件>`** | `cytoscape-impl` 源码 `Parser.java` |

### ⚠️ 必须纠正的一条谣传

网上（CSDN 等）流传「用 `-N` 参数以无界面模式运行」。**核对官方源码后确认：不存在这个参数。** `headless-cmdline-parser-impl` 的 `initOptions()` 只注册了 `-h`、`-v`、`-c` 三个选项。

照抄这个说法写脚本，会得到"参数被静默忽略、GUI 照常拉起、在服务器上因无 DISPLAY 直接崩"的后果。**本 Skill 不采用任何未经验证的参数。**

Cytoscape Desktop 本质是 GUI 应用：**无显示器的 Linux 必须用 `xvfb-run` 包裹**，这一点在 `docs/03` 里给了明确命令。

## 2. 路线对比与决策

| 路线 | 做法 | 结果一致性 | 跨 Agent | 工作量 | 结论 |
|---|---|---|---|---|---|
| **A. 重写/移植** | 用 Python/JS 重实现 Cytoscape 的算法 | ❌ **必然不一致**，违反硬约束 | ✅ 好 | 极大（7 仓库 + 20 app） | **排除** |
| **B. 驱动原版引擎** | Skill 只做生命周期管理 + 调用 CyREST/Commands | ✅ **天然一致**（就是原代码算的） | ✅ 好 | 中 | **选它** |
| **C. 混合** | B 为主，少量 Python 做 I/O 与格式适配 | ✅ 一致 | ✅ 好 | 中 | B 的自然形态 |

### 决策：路线 B（等价于 C）

理由用一句话说清：**只要不重写算法，"结果一模一样"就是构造性成立的，而不是"努力保证"的。** 这比任何测试都可靠。

## 3. 架构

```
┌─────────────────────────────────────────────────────────────┐
│  宿主 Agent（任意）                                          │
│  Claude Code / Codex CLI / Copilot / Claude Desktop / 其他   │
└───────────────┬─────────────────────────┬───────────────────┘
                │ 通道 1：MCP             │ 通道 2：Shell CLI
                │ (Streamable HTTP)       │ (最通用，兜底)
                ▼                         ▼
┌───────────────────────────┐  ┌──────────────────────────────┐
│ 官方 Cytoscape MCP Server │  │  cyctl（本项目，零依赖 Python）│
│ (cytoscape-desktop-mcp)   │  │  env/provision/start/wait/    │
│ 25 个工具，含              │  │  cmd/rest/run/mcp/stop        │
│ command_gateway_invoke  ★ │  └──────────────┬───────────────┘
└─────────────┬─────────────┘                 │
              │  HTTP  localhost:1234          │
              ▼                                ▼
┌─────────────────────────────────────────────────────────────┐
│         Cytoscape 3.10.5（原版 Java 引擎，版本锁定）          │
│   CyREST /v1/  ·  Commands API /v1/commands/                 │
│   ← 所有算法、统计、布局、样式计算都在这一层完成              │
└─────────────────────────────────────────────────────────────┘
```

**★ `command_gateway_invoke` 是关键**：官方 MCP 提供这个工具，可以调用**任意** Cytoscape 命令。它是命令语言的逃生舱口，也是"功能覆盖"能贴近上限的原因。

两条通道的分工：

- **通道 1（MCP）**：宿主原生支持 MCP 时首选。无需额外进程，工具描述由 Cytoscape 自己发布（`/mcp/manifest`），LLM 能直接看到语义化的工具schema。
- **通道 2（cyctl CLI）**：**最通用**。任何能执行 shell 的 Agent 都能用，包括不带 MCP 能力的宿主。输出契约固定（stdout 只放 JSON），便于程序化串联。

## 4. 「全部功能」的天花板（必须说清）

这是本方案里唯一需要你接受"打折"的地方，我不含糊其辞：

**可自动化的功能 = 上限。纯鼠标交互的操作 = 不可自动化，也不属于"可复刻"的范畴。**

| 类别 | 覆盖情况 |
|---|---|
| 网络导入/导出、会话存取、NDEx 往返 | ✅ 完整（命令语言） |
| 布局算法（全部已安装布局） | ✅ 完整 |
| 可视化样式：默认值、映射（连续/离散/直通）、bypass | ✅ 完整（CyREST 函数 + MCP 工具） |
| 表格数据：导入、列操作、映射、筛选 | ✅ 完整 |
| 选择操作、邻居扩展、分组、折叠 | ✅ 完整 |
| 网络分析：度、中心性、聚类等（随所装 App） | ✅ 取决于已安装 App |
| 应用管理（安装/启用/列出） | ✅ 命令语言支持 |
| 任意命令的通用入口 | ✅ `command_gateway_invoke` / `cyctl cmd` |
| **手工框选、拖拽节点、鼠标微调视觉效果** | ❌ 本质是 GUI 交互，不可脚本化 |
| **交互式调节可视化参数的实时预览** | ⚠️ 参数可设，但"边拖边看"不可 |
| **导出图片的逐像素一致** | ⚠️ 见 `docs/02` 渲染差异章节 |

**换句话讲**：Cytoscape 作为**计算引擎**的能力可以完整驱动；作为**交互式绘图板**的手感无法复刻——后者本来也不是"结果"，谈不上"结果一致"。

## 5. 关于「零 bug / 长时间稳定」的诚实答复

**我不能承诺"没有任何问题"。** 任何声称做到的交付都是不可信的。我能承诺的是把风险显式化并逐项建机制：

| 风险 | 已落地的机制 | 位置 |
|---|---|---|
| 版本漂移改变算法输出 | 版本锁死在 `assets/versions.lock.json`，升级必须显式改文件 + 重跑回归 | `versions.lock.json` |
| 下载包被篡改/损坏 | 官方 `sha256sums` 交叉校验；官方未覆盖的归档**默认阻断**（fail-closed）而非静默信任 | `cmd_provision` + 测试 |
| 恶意归档写出目标目录（Zip/Tar Slip） | 解压前逐条校验条目路径与链接指向，越界即拒绝 | `_extract` + 恶意归档用例 |
| 下载中断留下半截文件被复用 | 写 `.part` + `os.replace` 原子改名；校验 Content-Length | `_download` + 测试 |
| 命令端点映射错位 | 逐字复刻官方 `py4cytoscape` 算法，并写测试锁死 | `cyrest.py` + 测试 |
| **HTTP 200 但命令实际失败**（静默失败） | 识别响应体里的 `errors` / `error` 字段并判为失败 | `cyrest_request` |
| 企业代理劫持本机请求（实测会拿到 502） | 默认绕过代理 | `_build_opener` + 行为级回归测试 |
| 环境不满足（如 Java 8） | `cyctl env` 显式报告 `ok_for_cytoscape: false`，不静默失败 | `detect_java` |
| 结果不可追溯 | `cyctl run` 产出溯源清单（引擎版本 + 输入哈希 + 每步 `result_sha256`） | `cmd_run` |

**当前状态**：以上机制均已实现，**159 个单元测试全绿**（含归档安全、下载稳定性、宿主矩阵、
MCP 桥、引擎发现、MCP 直连协议往返与 run/rest 契约用例）。真实引擎端到端联调与确定性
验证的完整记录见 `docs/07-验证与稳定性报告-2026-10-01.md`。
全平台 / 全引擎 / 全宿主的覆盖矩阵见 `docs/05-全平台全引擎全宿主矩阵.md`。
**未验证项**（见 §7）：与真实 Cytoscape 引擎的联调尚未执行。
