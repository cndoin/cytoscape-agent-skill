# 08 · 上游对齐审计报告（2026-10-02）

> 审计对象：`cytoscape-agent-skill`（cyctl 0.4.0）
> 审计方法：上游符号面 AST 提取 + **每个端点发真实请求** + 逐入口实跑取证
> 一句话结论：**引擎能力面无缺口（0 条因工具自身写错而跑不了）；但发现并修掉 7 个真实缺陷，
> 其中 1 个是「成功信封里装垃圾」级别的静默数据损坏。**

### 4.2 与上游的**两处有意偏离**（必须写明，不装作逐字一致）

1. **不提供 470 个同名便捷函数，只提供通用入口。**
   `cyctl cmd` / `cyctl rest` 是「引擎能力的通用表达」，任意命令、任意端点都能打。
   理由：本项目的第一原则是「结果与原版一模一样 ⇒ 绝不重写算法」。若自己包一层
   `getNetworkSuid()` 之类的便捷函数，就引入了第二份实现，也就引入了漂移风险。
   **等价性由引擎保证，而不是由我们的封装保证。**

2. **危险命令默认拒绝，上游客户端不管这个。**
   CyREST 的 `GET /commands/{ns}/{cmd}` 对**无参命令**就是执行它。
   `py4cytoscape` 直接照发；我们永久拒绝 quit/exit/shutdown/halt（见 §6.4）。

### 4.3 我们比上游**多**的部分

| 额外能力 | 说明 |
|---|---|
| 9 个 App 命名空间的 29 条命令 | `py4cytoscape` 无对应封装（cybrowser / cychart / analyzer / filetransfer / enrichment / idmapper / mapSourceAndTarget / diffusion / enhancedGraphics） |
| `cyctl provision` / `doctor` / `discover` / `prune` / `wait` / `stop` / `bridge` / `mcp` / `run` | 引擎生命周期、完整性校验、宿主接入、溯源清单 —— 上游客户端完全没有 |
| 字节精确的二进制导出（`rest --out`） | 上游客户端用 requests，无此问题；我们的 stdlib 实现原本有，现已修（§6.1） |

## 5. 逐入口实跑取证

### 5.1 REST 端点：106 个 GET 全探（走真实 CLI 入口）

```
GET 端点 106 条 —— 探了 104，声明不探 2

  ok                97     真正可达
  expected_absent    6     引擎**按语义**返回 404（资源本就不存在）
  upstream_500       1     上游对不适用输入回 500（有反证，见下）
  declared_skip      2     明确声明不探（附理由）
  --------------------------------
  失败               0     没有任何一条是「因为工具自身写错而跑不了」

  按通道：bytes 9 条（失败 0） / text 95 条（失败 0）
```

**这本报告第一版的 §5.1 数字是错的，必须说明。** 第一版写成「未通过 20 条」，
并把归类手数成「4 / 6 / 7 / 3」。重跑时发现三件事：
① 探测脚本自己漏了 `commands/{ns}/{cmd}` 的 `Accept` 声明；
② 探测脚本给 `collections/*` 传的不是**根网络** SUID（`/v1/collections` 实测返回 `[155]`，
而它传的是普通网络）；③ `.cx` 端点的产物魔数写错了（见下）。
所以第一版的「未通过」里混着**探针自身的错**。现改为由脚本自动定级、每次落盘，
**数字可复现，不靠人眼统计**。

**6 条 `expected_absent` 的逐条依据**（引擎返回 404 是语义正确，不是坏了）：

| 端点 | 为什么 404 |
|---|---|
| `networks/{id}/groups/{node}` | 该网络没有分组 —— `networks/{id}/groups/count` 实测 `{"count":0}` |
| `…/groups/{node}/collapse` | 同上，没有分组可折叠 |
| `…/groups/{node}/expand` | 同上，没有分组可展开 |
| `networks/{id}/nodes/{node}/pointer` | pointer 是「嵌套网络的 SUID」；该节点没有嵌套网络 |
| `views/{id}/network/{vp}/bypass` | 该网络在该视觉属性上没有 bypass |
| `views/{id}/nodes/{n}/{vp}/bypass` | 该对象在该视觉属性上没有 bypass |

**1 条 `upstream_500`**：

| 端点 | 反证 |
|---|---|
| `collections/{id}/tables/{tableType}/columns` | **同一能力**在 `/v1/networks/{id}/tables/{tableType}/columns` 下实测 **200** 并返回真实列定义；`collections` 变体无论传 `defaultnode` 还是 `defaultnetwork` 都回 **500**（应 4xx）。属上游缺陷，见 §7.4 |

**2 条 `declared_skip`**：`/v1/session`（需磁盘上已有的 session 文件）、
`/aMatReader/v1/predictParameters`（需真实 `.amat` 文件）—— 理由已写入证据文件，不是偷偷跳过。

> **结论：97 条可达 + 6 条语义正确 + 1 条上游缺陷 + 2 条声明不探 = 106。
> 没有任何一条是「因为工具自身写错而跑不了」。**

### 5.1.1 顺带纠正一个事实：`.cx` 端点返回的是 CX **JSON**，不是 zip

第一版探测脚本把 `.cx` 的产物魔数写成 `PK\x03\x04`（zip），于是三条 `.cx` 端点被误判为
「产物魔数不符」。实测：

```
GET /v1/networks/10397.cx  →  http_status 200
   content_type: application/json
   size: 119,641 字节
   头 60 字节: [{"numberVerification":[{"longNumber":281474976710655}]},{"metaData":…
   尾 40 字节: …{"status":[{"error":"","success":true}]}]
```

即 CyREST 的 `.cx` 端点给出的是 **CX aspect 流（JSON 形态）**，不是 CX2 的 zip 包。
脚本现已接受两种前缀，并把这条事实写进注释与证据文件。

每条都断言：退出码 ∈ {0,2,3,4,5}、stdout 是**单一** JSON 对象。

修复**前**：31 个用例 1 个失败（`--help` 输出纯文本）。
修复**后**：**31 个用例，未通过 0，跳过 0**（`evidence/cli-entry-audit.json`）。

## 6. 本轮发现并修掉的缺陷（7 个）

### 6.1 ★ 二进制导出被静默损坏（最严重）

- **现象**：`cyctl rest GET networks/196/views/2292.png` 返回 `ok: true, http_status: 200`，
  但 `result` 是一个字符串，其中 **28,798 个字符是 U+FFFD 替换字符**。
- **根因**：`cyrest_request` 对响应体做 `.decode("utf-8", errors="replace")`。
  二进制里的非 UTF-8 字节被替换掉，**不可逆**。
- **为什么危险**：这是「成功信封里装垃圾」。调用方看到 200 + ok:true，
  会以为图片已导出；实际拿到的是坏数据。比报错危险得多。
- **影响范围**：`views/*.png`、`views/*.pdf`、`networks/*.cx`（zip）。
  `.svg` / `.csv` / `.tsv` 是文本，不受影响（实测 0 个替换字符）。
- **修复**：新增 `cyrest.cyrest_download()` 字节通道 + `cyctl rest --out <file>`。
  实现要点：`.part` + `os.replace` 原子落盘；校验 `Content-Length` 防截断；
  补一次「200 + JSON 错误信封」判定，避免把错误页当产物；默认 `Accept: */*`。
- **回归**：`TestBinaryDownloadContract`（5 例）+ 实引擎的字节精确性与可重复性用例。

### 6.2 operation 路径含空格 → 退出码 1（违反输出契约）

- **现象**：`cyctl rest GET "commands/network/get preferred"` → `退出码 1`，stdout 是内部错误信封。
- **根因**：urllib 对含空格的 URL 抛 `http.client.InvalidURL`；该异常既不是 `OSError`
  也不是原先捕获的类型，一路穿透到 `main` 的兜底分支，变成「内部错误 / 退出码 1」。
- **为什么重要**：契约规定退出码只能是 0/2/3/4/5。按契约解析的调用方遇到 1 会当成未知灾难。
  而 `commands/{ns}/{cmd}` 正是这一类端点。
- **修复**：新增 `_encode_operation()`（只编码路径、保留已写的 `%XX`、查询串原样透传）；
  `Request` 构造纳入 try 范围；`InvalidURL`/`ValueError` 归类为 `kind="usage"` → 退出码 2。

### 6.3 `--help` 输出非 JSON（违反输出契约）

- **现象**：`cyctl --help` → 退出码 0，但 stdout 是纯文本 usage，`json.loads` 直接炸。
- **同类先例**：`error()` 与 `--version` 早就为同一个原因被 JSON 化，help 是漏掉的一处。
- **修复**：覆写 `ArgParser.print_help()`，输出 `{"ok":true,"usage":…,"help":…}`。
  一处覆盖主解析器与全部子解析器（`add_subparsers` 默认继承父解析器类型）。

### 6.4 ★ 危险命令保护可被绕过（保护形同虚设）

- **背景**：CyREST 的 `GET /commands/{ns}/{cmd}` 对**不需要参数**的命令就是执行它 ——
  没有「只看帮助」这一说。`command quit` 会把引擎关掉，且 GUI 模式下 JVM 会卡在退出
  确认对话框上不退出，留下一个占 GB 的僵尸进程而端口已关。
- **漏洞**：上一轮只拦了 `cyctl commands`。实测 `cyctl cmd "command quit"`、
  `cyctl rest GET commands/command/quit`、以及工作流步骤**都能绕过去**。
- **修复**：把判定收到**访问层**（`cyrest.dangerous_command` / `dangerous_operation`），
  `run_command` / `call_operation` / `cyrest_download` 三个出口统一过闸，工作流步骤也显式判定。
  退出码 2，`kind="danger"`。**不误伤**：只认命令名的第二个词，
  `network set attribute name="halt"` 正常放行（已实测）。
- **回归**：`TestDangerCommandGuard`（9 例，含「两张动词表不得漂移」的断言）。

### 6.5 ★ `cyctl stop` 的优雅退出从来没生效过

- **现象**：`stop` 一直报 `graceful: false`、`stopped_by: kill-pid-file`。
- **根因**：优雅退出发的是 **POST** `/commands/command/quit`，却带了 `Accept: text/plain`。
  实测：

  | 请求 | 结果 |
  |---|---|
  | `POST /v1/commands/network/list` + `Accept: text/plain` | **HTTP 406** |
  | `POST /v1/commands/network/list` + `Accept: application/json` | HTTP 200 |

  只有 **GET** 的 help 端点要 `text/plain`。而原来的 except 分支把所有异常都写成
  「进程关闭会中断连接，这不代表退出失败」—— 一个**持续存在**的 406 被这句话盖住，
  优雅退出静默失效，每次都回落到杀进程（而 pid 文件已被记录为不可靠）。
- **修复**：`Accept: application/json`；并把 **4xx 与「连接中断」分开**，
  4xx 明确记为「请求被拒绝，引擎没收到退出指令」。
- **效果**：修复后 `graceful: true`、`http_status: 200`、2 秒关端口、**无残留进程**。
- **回归**：两条源码级断言（Accept 必须是 json；必须区分 4xx）。

### 6.6 `commands --allow-execute` 的 `executed` 标志误报

- **现象**：`cyctl commands network export --allow-execute` 只拿到一份**参数清单**，
  却报 `executed: true`。调用方会以为导出文件已经生成。
- **修复**：按回应标题区分。`Available arguments for …` ⇒ `executed:false, mode:"help"`；
  否则 `executed:true, mode:"executed"`。实测两条路径均正确。
- **回归**：`test_help_mode_is_not_reported_as_executed` / `test_real_run_is_reported_as_executed`。

### 6.7 工作流输入路径未规范化

- **现象**：工作流里写 `../data/galFiltered.sif`，`{input}` 展开成 `…/workflows/../data/galFiltered.sif`
  并原样交给引擎，引擎据此给网络命名 —— 同一文件因写法不同就变成**两个名字不同的网络**
  （实测 `networks.names` 里同时出现两种写法）。而输入路径是溯源清单的关键字段。
- **修复**：`_abs()` 返回 `resolve()` 后的绝对路径。

### 附：审计过程中修掉的 5 处**审计工具自身**缺陷

审计工具也是代码，也会错。**把自己的错算到被审对象头上，是审计里最危险的失误**，
所以逐条记下来：

| # | 缺陷 | 说明与后果 |
|---|---|---|
| 1 | 探测脚本把 swagger 的 `/v1` 前缀原样传给 `cyctl rest`（它自己会拼 `/v1`） | 106 条里 **102 条假 404**。第一版结论完全错误，靠逐条看 URL 才发现 |
| 2 | 探测脚本写死网络/视图 ID | 换一次会话全部 404。改成现场导入 + 现场取 ID |
| 3 | 测试里假定「59999 端口必然空闲」 | 不可验证的假设。同一次会话里 `cyctl start --port 59999` 真的在 59999 起了第二个引擎（1.47 GB + 1.22 GB 两个 java 进程），用例假失败。改成现场探测空闲端口 |
| 4 | `audit_cli_contract.py` 把 `int` 端口号直接拼进 argv | `subprocess` 的 `list2cmdline` 抛 `TypeError`，脚本在最后两条用例上崩掉。argv 元素必须是 `str` |
| 5 | 探测脚本给 `collections/*` 传了非根网络 SUID、给 `.cx` 写了 zip 魔数 | 前者造成 3 条本应 200 的端点被记成 500；后者造成 3 条 `.cx` 被记成「魔数不符」。两处都是**探针的错**，修完 `unpassed` 从 20 降到 0 |

> 教训：**「未通过」的条数本身就是个需要取证的结论。** 一旦分类靠手数，
> 探针的错误就会伪装成被审对象的缺陷。现在定级逻辑写进脚本、结果落盘（`verdict` 字段），
> 任何人重跑都能复核。

## 7. 上游自身的失效 / 不一致（**不作为复刻对象**）

审计不只找自己的问题，也找上游的 —— 把坏行为「忠实复刻」过来是更糟的选择。

| # | 问题 | 证据 | 我们的处置 |
|---|---|---|---|
| 7.1 | `GET /commands/{ns}/{cmd}` 对无参命令**即执行**，没有纯查询语义 | `cyctl commands command quit` 真的关掉引擎；JVM 卡在退出框留下 1.3 GB 僵尸 | 永久拒绝 quit/exit/shutdown/halt；其余只做只读存在性查询 |
| 7.2 | POST 命令端点的 `Accept` 与 GET help 端点**相反** | POST + `text/plain` → 406；POST + `json` → 200 | 文档 + 源码断言锁定（§6.5） |
| 7.3 | `views/*.pdf`、`*.svg` 对 `Accept` 敏感 | 发 `application/json` → 406 | `--out` 默认 `Accept: */*`；`--accept` 可覆盖 |
| 7.4 | 非法输入回 **500** 而非 4xx | ① `collections/{非根网络}/subnetworks` → 500（`/v1/collections` 语义是「根网络」，传普通网络本应 4xx）；② `collections/{id}/tables/{tableType}/columns` → 500，**而同一能力在 `/v1/networks/{id}/…` 下 200**；③ `styles/visualproperties/{vp}/values` 对连续型 VP → 500，而对离散型 `NODE_SHAPE` → 200 且返回枚举值 | 不改上游；`rest` 如实转述 HTTP 状态，文档标风险 |
| 7.5 | `/mcp/manifest` 只文档化 4 个工具，实际 25 个 | manifest vs `tools/list` | 文档明确：**工具清单的事实源是 `tools/list`** |
| 7.6 | App 端点挂在**端口根**，不在 `/v1` 下 | `/cyndex2/v1` 在根上 200，在 `/v1` 下 404 | 文档给出 `--base-url http://localhost:1234` 的用法 |
| 7.7 | `layout` 命名空间下**没有** `getLayoutNames` | 真实命令是 `get preferred`（该命名空间共 20 条） | 示例工作流改用真实命令名；「绝不猜名字」写进铁律 |
| 7.8 | `swagger.json` 用**平台行分隔符**序列化 | Windows 实测返回 **CRLF**（头 15 字节 `{\r\n  "swagger" : "2.0"`，6636 个 CR / 6636 个 LF）；Linux 上会是 LF | 证据快照**保留上游原样字节**，不做换行规范化；打包自检对它有显式豁免（`tools/package.py` 的 `CRLF_ALLOWED`，附理由） |
| 7.9 | `.cx` 端点的产物是 CX **JSON 而非 zip** | `GET /v1/networks/{id}.cx` → `Content-Type: application/json`，119,641 字节，头 `[{"numberVerification"`、尾 `{"status":[{"error":"","success":true}]}` | 探测脚本接受两种前缀；事实写进 §5.1.1。驼峰命名 `networks/{id}/views/{viewId}.cx` 容易让人以为一定是二进制包，实际不是 |
| 7.10 | `swagger.json` **字节不稳定**：同一版本另起会话重取，内容语义相同但字节不同 | 证据快照 252,662 B（sha256 `d1158d52…`）vs 现场重取 252,666 B（sha256 `bd5db0e6…`），差 4 字节。逐项核对：路径集合与操作数**完全一致**（119 / 171 / GET 106），差异来自 ① 路径**顺序**不同（`/aMatReader/v1/predictParameters` 与 `/extend/{networkSUID}` 互换位置）；② `operationId` 的去重后缀归属换边（`diffuseWithOptions` ↔ `diffuseWithOptions_<hash>`）；③ `/v1/commands` 与 `/v1/commands/{namespace}` 的描述文字在 `"text/plain"` 与 `"text/html"` 之间摆动 | 快照保留上游原样字节（含 CRLF）供离线取证，但**明确声明其 sha256 不可当回归基准**；凡是依赖它的结论只用顺序无关的量（路径集合、操作数）。见 §3.1 的警示框 |

## 11. 复现方式

审计脚本已归档为仓库的一部分（`tools/audit/`），**不是一次性草稿** ——
第四节那句「复现方式」要能真的跑起来，否则结论就不可复核。

```bash
SK=.                                          # 技能包根目录

# 0. 起引擎（无引擎时下面的脚本会以退出码 3/4 明确报错，不会假装成功）
python $SK/scripts/cyctl.py start && python $SK/scripts/cyctl.py wait

# 1. 拉取上游 REST 面权威清单（swagger 快照，106 条 GET 的依赖）
python $SK/scripts/cyctl.py rest GET swagger.json \
       --out $SK/evidence/engine-swagger-3.10.5.json

# 1b. 复现 §7.10「swagger 字节不可复现」：再取一份，比对语义与字节
#     （落到 .cache/ 而不是 /tmp —— 原生 Windows 的 python 不认 /tmp）
python $SK/scripts/cyctl.py rest GET swagger.json --out $SK/.cache/swagger-again.json
cd $SK && python - <<'PY'
import hashlib, json
a = json.load(open("evidence/engine-swagger-3.10.5.json", encoding="utf-8"))
b = json.load(open(".cache/swagger-again.json", encoding="utf-8"))
ab = open("evidence/engine-swagger-3.10.5.json","rb").read()
bb = open(".cache/swagger-again.json","rb").read()
print("字节相同:", ab == bb, "|", hashlib.sha256(ab).hexdigest()[:16], hashlib.sha256(bb).hexdigest()[:16])
print("路径集合相同:", set(a["paths"]) == set(b["paths"]), "| 路径数:", len(a["paths"]), len(b["paths"]))
print("tags 数组:", len(a["tags"]), "| 被操作引用的 tag:",
      len({t for ms in a["paths"].values() for op in ms.values()
           if isinstance(op, dict) for t in (op.get("tags") or [])}))
PY

# 2. 枚举引擎命令面（23 命名空间 / 195 命令）→ evidence/engine-command-surface.json
python $SK/tools/audit/engine_command_surface.py

# 3. 枚举官方客户端函数面（35 模块 / 470 函数）→ evidence/py4cytoscape-1.13.0-surface.json
python -m pip download py4cytoscape==1.13.0 --no-deps -d $SK/.cache/upstream
python $SK/tools/audit/upstream_client_surface.py

# 4. 逐端点真实请求（走真实 CLI 入口）→ evidence/rest-endpoint-probe.json
python $SK/tools/audit/probe_rest_endpoints.py

# 5. 逐入口实跑 + 契约断言 → evidence/cli-entry-audit.json
python $SK/tools/audit/audit_cli_contract.py

# 6. MCP 协议往返
python $SK/tools/mcp_e2e.py

# 7. 全量回归（含实引擎用例；脚本 4/5 需要引擎在跑）
cd $SK && python -m unittest discover -s tests -v
```

**退出码约定（四个审计脚本一致）**：`0` 全部通过 / `3` 缺前置（引擎没起、swagger 快照缺失、
wheel 找不到）/ `4` 有端点或用例未通过。**只有 `0` 才算通过**，
`3` 与 `4` 都不允许被当成「跑过了」。

> 脚本 2 会真实地**改一次引擎状态**（导入示例网络以取得现场 ID），脚本 4 同理；
> 两者都只做只读探测 + 一次导入，不落盘到引擎之外。
> 脚本 5 的端口占用用例传的是**引擎正在用的端口**（命中「端口已被占用」直接返回），
> 不会启动第二个实例；引擎没起时该用例明确登记为跳过。
