# 02 · 功能覆盖与确定性边界

本文回答两个必须量化的问题：**能驱动多少功能**、**什么情况下结果会变**。

---

## 1. 功能覆盖矩阵

自动化接口分三层，覆盖面从大到小：

1. **命令语言（Commands）** —— 官方命令行对话框的脚本化形式，覆盖面最大。
2. **CyREST 函数（`/v1/...`）** —— 直接的 REST 资源接口。
3. **官方 MCP 工具** —— 25 个高封装工具，面向 LLM 使用。

### 1.1 官方 MCP 工具清单（实测抓取，25 个）

抓自 `http://localhost:1234/mcp/manifest`（快照见 `evidence/cytoscape-mcp-manifest.md`）：

| 分组 | 工具 |
|---|---|
| 网络与视图 | `load_cytoscape_network_view`、`get_loaded_network_views`、`set_current_network_view`、`create_network_view` |
| 表格与文件 | `inspect_tabular_file`、`get_file_columns`、`table_import_file` |
| 分析 | `analyze_network` |
| 布局 | `get_layout_algorithms`、`apply_layout` |
| 样式-默认值 | `get_visual_style_defaults`、`set_visual_default` |
| 样式-映射 | `get_mappable_properties`、`get_compatible_columns`、`get_column_range`、`get_column_distinct_values`、`create_continuous_mapping`、`create_discrete_mapping`、`create_discrete_mapping_generated`、`create_passthrough_mapping` |
| 样式-整体 | `get_styles`、`switch_current_style` |
| **通用逃生舱** | `command_gateway_search`、`command_gateway_get`、**`command_gateway_invoke`** |

`command_gateway_invoke` 是本方案能贴近"全部功能"的关键：它允许调用**任意**已注册的 Cytoscape 命令。因此**命令语言能做的，Skill 就能做**。

### 1.2 通过 `cyctl cmd` / `command_gateway_invoke` 可覆盖的功能域

下表按官方 RCy3 / py4cytoscape 的能力分类组织（这组分类本身就对应自动化面）：

| 功能域 | 典型命令/操作 | 覆盖 |
|---|---|---|
| 网络创建与导入 | `network import file` / `import url` / `create` | ✅ |
| 网络导出 | `network export` | ✅ |
| 会话 | `session save` / `session open` / `session new` | ✅ |
| NDEx 往返 | `cyndex` 命名空间 | ✅（需联网） |
| 选择 | `network select`、`select firstNeighbors`、反向选择 | ✅ |
| 布局 | `layout`（列出并应用全部已装布局）、`layout getLayoutNames` | ✅ |
| 样式默认值 | `vizmap set default` | ✅ |
| 样式映射 | 连续/离散/直通映射、`getCompatibleColumns` | ✅ |
| 样式 bypass | 单元素覆写 | ✅ |
| 可视化/视图 | `view fit content`、缩放、导出图片 | ✅ |
| 表格 | `table import file`、列重命名/删除、列映射 | ✅ |
| 筛选 | 度筛选、列筛选、组合筛选 | ✅ |
| 分组 | `group create` / `collapse` / `expand` | ✅ |
| 应用管理 | `apps install` / `enable` / `list` / `status` | ✅ |
| 图论分析 | 中心性/度/聚类等 —— **取决于已安装的 App** | ⚠️ 见下 |

> ⚠️ **分析类功能的覆盖 = 你装了什么 App。** Cytoscape 的核心分析能力（度分布、最短路等）在核心命令里，但大量高级分析（如各种富集、聚类、通路分析）由第三方 App 提供。**必须把 App 集合也纳入版本锁定**，否则"同一个 Skill"在不同机器上能力不同、结果不同。见 §2.5。

### 1.3 明确无法覆盖的部分

| 项 | 原因 |
|---|---|
| 手工框选、拖拽布局、鼠标微调 | 本质是 GUI 人机交互，无脚本接口 |
| 交互式实时预览（边调参数边看效果） | 只有"设置值"的接口，没有"持续预览"的接口 |
| 导出图片逐像素一致 | 见 §2.3 |
| install4j 打包/签名等开发链 | 超出使用范围 |

## 2. 确定性边界（结果为什么会变）

这是医学场景的核心章节。**"结果一样"需要主动构造，不能假设。**

### 2.1 布局算法的随机性 ★ 最常见

**很多布局是随机初始化的（力导向、MCL、部分 yFiles 布局）。** 同一输入、同一版本，两次运行会得到不同坐标。

对策：
- 优先选**确定性布局**（如 `grid`、`circular`、`hierarchical` 类）。
- 若必须用力导向类，**固定随机种子**。Cytoscape 部分布局暴露了 seed 参数（在 Command 的 `getLayoutProperties` 里查），能设就设。
- 若布局**不暴露种子**：坐标不可复现是既定事实——此时**把可复现性建立在"布局不参与结论"的前提上**（即：分析结论只依赖拓扑与属性，不依赖节点坐标）。这是生信工作中的正确做法。

> 结论：节点坐标不是"结果"，拓扑 + 属性 + 表数据才是。请把回归比对做在后者上。

### 2.2 远端数据源会变 ★

`network import url`、NDEx 导入这类操作，内容由**远端服务器**决定。同一个 URL 今天和明天的内容可能不同。

对策：**先把数据落到本地、算哈希、锁定**。`cyctl run` 的 `inputs` 段就是为此设计——它会记录每个输入文件的 sha256。工作流里应当用本地文件路径，而不是远端 URL。

### 2.3 导出图片的像素级差异

导出的 PNG/PDF 受以下因素影响，跨机器必然有差异：

- 图形栈与驱动（尤其 OpenGL / 硬件加速路径）
- 可用字体集与字体版本
- DPI / 缩放设置
- 抗锯齿实现

对策：**图片不作为比对基准**。若确实需要发行版级别的图片一致性，需要在同一台机器、同一渲染后端（建议关掉硬件加速：`-Dsun.java2d.opengl.fbobject=false`，或强制软件渲染 `-Dprism.order=sw`）下生成。

### 2.4 浮点与并行度

部分算法使用多线程，归约顺序会影响最低有效位。

对策：对必须逐位可复现的分析，**固定 JVM 线程数**（如 `-Djava.util.concurrent.ForkJoinPool.common.parallelism=1`）并固定堆大小。代价是变慢。

### 2.5 App 集合与版本 ★

命令命名空间由**已安装的 App** 决定。装了 `Diffusion` 就有 `diffusion` 命名空间；没装就没有。

对策：把 App 清单和版本也写进版本锁定。可先跑一次：

```bash
cyctl cmd 'apps list installed'
```

把结果固化成基线，纳入回归。

## 3. 达成"可复现"的检查清单

要让一次运行可被第三方原样重现，需同时满足：

- [ ] **引擎版本固定** —— `assets/versions.lock.json` 的 `pinned.cytoscape`
- [ ] **JRE 版本固定** —— 用 Skill 自带的 JRE，而非系统 JAVA_HOME
- [ ] **App 集合固定** —— 记录 `apps list installed` 的输出
- [ ] **输入数据本地化并哈希** —— 工作流只引用本地路径
- [ ] **随机性被消除或隔离** —— 固定布局种子；或明确声明结论不依赖坐标
- [ ] **工作流文件本身被哈希** —— `cyctl run` 自动做
- [ ] **失败被显式暴露** —— 任何一步非 `ok` 就中断，绝不"继续跑完"

`cyctl run` 产出的溯源清单包含以上大部分字段：

```jsonc
{
  "schema": "cyctl/run-manifest/v1",
  "cyctl_version": "0.1.0",
  "workflow": { "path": "...", "sha256": "...", "name": "..." },
  "engine":  { "base_url": "...", "info": { /* GET /v1/ 的原始返回 */ } },
  "inputs":  [ { "path": "...", "sha256": "..." } ],
  "steps":   [ { "index": 0, "kind": "command",
                 "request": { "command": "...", "url": "...", "body": {...} },
                 "result": {...},
                 "result_sha256": "..." } ],
  "ok": true
}
```

`result_sha256` 是每步结果的指纹。**同一引擎版本 + 同一输入 + 同一工作流 ⇒ 指纹应完全一致。指纹变了，就是有人动了版本、数据或 App 集合。**

## 4. 一致性回归怎么做

升级引擎、换机器、改 App 集合之后，必须跑回归：

```bash
# 1) 基线（升级前）
cyctl run workflows/toy.sif.workflow.json --out baselines/before.json

# 2) 升级 / 迁移

# 3) 对照
cyctl run workflows/toy.sif.workflow.json --out baselines/after.json
python scripts/cmp_manifest.py baselines/before.json baselines/after.json
```

对照规则：

- `engine.info` 变了 → **预期之内**，但要记录
- `inputs[*].sha256` 变了 → **数据被改动，不是引擎问题**，停止比对
- `steps[*].result_sha256` 变了 → **真正的行为变化**，必须逐字段定位差异来源

> `scripts/cmp_manifest.py` 属于待补件（见 `docs/01` §7 的收尾清单）；当前可手工比对两个 JSON。

## 5. 常见坑（已实测）

| 坑 | 症状 | 处置 |
|---|---|---|
| 环境代理劫持本机请求 | 引擎在跑却报 HTTP 502 | cyctl 已默认绕过代理；自研脚本需注意 |
| 用网传的 `-N` 无头参数 | 参数被忽略，GUI 照常启动，服务器上崩 | 官方无此参数，勿用 |
| 无 DISPLAY 直接启动 | JVM 在 AWT/Swing 初始化阶段静默退出 | 用 `xvfb-run`（见 `docs/03`） |
| Java 版本不足 | 启动失败或行为异常 | `cyctl env` 会报 `ok_for_cytoscape: false` |
| 只信 HTTP 状态码 | 200 但命令失败被当成成功 | cyctl 解析响应体 `errors` 字段 |
| 多 Agent 并连同一引擎 | 命令互相干扰 | Cytoscape 是**单用户**应用；请串行化，或用独立实例 + 不同端口 |
