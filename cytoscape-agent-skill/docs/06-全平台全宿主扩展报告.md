### 1.1 三条引擎路线（这是「全都要」的核心）

```bash
cyctl start                 # auto：优先自带，没有则回落系统安装
cyctl start --engine bundled   # 自带，版本锁定，确定性最高（约 580 MB）
cyctl start --engine system    # 复用系统已装，0 下载
cyctl start --engine attach    # 接管已手工打开的实例，不启动新进程
```

**代价必须说清**：`system` / `attach` 的确定性低于 `bundled` —— 版本取决于用户装了什么。
所以 `cyctl run` 的溯源清单里 `engine.info` 是必需项，跨机比对前先核对版本。
这条已写进 `SKILL.md` 的铁律第 6 条。

## 3. 关键设计决策：为什么不能自动改写用户配置

`~/.claude.json` 里除了 MCP 服务器，还有项目历史、设置等；`~/.codex/config.toml` 与
`~/.gemini/settings.json` 同理。**整份重写 = 拿用户的环境赌博**。

因此 `write_config` 的策略是：

| 情况 | 行为 |
|---|---|
| 目标不存在 | 新建（安全） |
| 目标是**专用** MCP 配置文件 | **合并**：只增改 `cytoscape-mcp` 一个条目，其它键原样保留，改动前生成 `.cyctl-bak` |
| 目标是**混合**配置文件 | **拒绝改写**，只输出内容让用户手工合并（需 `--allow-mixed` 显式覆盖） |
| 现有内容不是合法 JSON / 顶层不是对象 / `mcpServers` 不是对象 | **拒绝**，一字不改 |
| 内容已是最新 | 报 `unchanged`，不写盘 |
| 未加 `--write-config` | **完全不写盘**，只打印 |

判定「专用 vs 混合」用文件名：`config.toml` / `settings.json` / `.claude.json` 视为混合。
这一层有 7 个用例锁定，包括「被拒绝时文件字节必须完全不变」。

## 4. 桥的协议要点（都有测试）

MCP stdio 与 Streamable HTTP 之间不是简单的中转，有 4 个必须处理的点：

1. **会话头 `Mcp-Session-Id`**：服务端在 `initialize` 响应里返回，后续请求必须带上。
   丢了会话 = 「初始化成功但工具列表为空」。桥对 `initialize` **同步处理**，确保先拿到会话 id。
2. **`MCP-Protocol-Version`**：从 initialize 结果里读出并回填到后续请求。
3. **`Accept: application/json, text/event-stream`**：不声明接受 SSE，服务端可能不回流式响应。
4. **SSE 响应解析**：服务端可能用 `text/event-stream` 返回，需要按事件边界抽 `data:` 负载。
   同时通知类消息返回 **202 Accepted（无 body）**，不得产生任何输出。

另有一条硬约束：**stdout 上只能有 JSON-RPC 消息**，日志一律走 stderr。
这是全包唯一一个不遵守「stdout 一个 JSON 信封」契约的命令，已在 `describe` 与文档里显式标注。

## 6. 仍然存在的空白（不粉饰）

1. **端到端联调没跑** —— 需下载约 580 MB 并拉起 GUI 程序。所有需要真实引擎的路径
   （`cmd` / `rest` / `run` / MCP 全链路）都只有协议层验证，没有真实往返。
   这是当前唯一的功能性空白。
2. **`system` / `attach` 引擎路线只有「找不到」的失败路径被测过** ——
   本机没装 Cytoscape，成功路径无法验证。发现逻辑本身有合成用例覆盖。
3. **桥的并发是「initialize 同步 + 其余多线程」** —— 未做压力测试；
   Cytoscape 本身是单用户应用，多 Agent 并发会互相干扰（官方文档明确说明）。
4. **Windsurf / Devin 的配置路径处于变更中** —— 两条候选路径都保留，需要用户在具体版本上验证。
