# 05 · 全平台 / 全引擎 / 全宿主矩阵

这份文档回答一个问题：**「全都要」到底覆盖了什么，以及哪些是官方就做不到的。**

结论放前面：**三条引擎路线、三个平台、两类架构、九类宿主全部可用**；
真正的天花板只有两处，且都写明了（§4）。

## 1. 平台 × 架构矩阵

| 平台 | 架构 | 官方自带引擎产物 | 官方 JRE 包 | 无头（无显示器） |
|---|---|---|---|---|
| Windows | x64 | ✅ `.exe` 安装包（**有官方 sha256**）/ `.zip`（无哈希） | ✅ `windows-amd64-17.0.5.tar.gz`（无哈希，TOFU） | 不需要虚拟显示 |
| Windows | ARM64 | ❌ 官方未发布 | ❌ | 走 `--engine system`（x64 仿真） |
| Linux | x64 | ✅ `.sh` 安装包（**有官方 sha256**）/ `.tar.gz`（无哈希） | ❌ 官方无 Linux 包 → 用发行版 OpenJDK 17 | `xvfb-run`，`cyctl start --headless` 自动套 |
| Linux | ARM64 | ❌ 官方未发布 | ❌ | 走 `--engine system` |
| macOS | Intel | ✅ `macos_x64.dmg`（**有官方 sha256**）/ `.tar.gz`（无哈希） | ❌ | 不需要 |
| macOS | Apple Silicon | ✅ `macos_aarch64.dmg`（**有官方 sha256**）/ `.tar.gz`（无哈希） | ✅ `macos-aarch64-17.0.5.tar.gz`（无哈希，TOFU） | 不需要 |

> 事实来源：官方 release 的 `sha256sums` 清单（已归档在 `evidence/official-sha256sums-3.10.5.txt`，
> 测试会重新拉取并与锁定文件逐字比对）。**官方清单只覆盖 4 个安装包**，
> 所有 `tar.gz` / `zip` 归档与官方 JRE 都没有哈希 —— 这一点在锁定文件里标为 `null` / `tofu`，
> 不做任何美化。

**多架构选型**：`cyctl provision --component cytoscape --variant <name>`，
可用变体见 `assets/versions.lock.json` 的 `artifacts.cytoscape.<平台>[*].variant`。

## 2. 三种引擎来源

| 模式 | 命令 | 下载量 | 确定性 | 什么时候用 |
|---|---|---|---|---|
| **bundled** 自带 | `cyctl provision …` → `cyctl start` | 约 580 MB | **最高**：版本被 `versions.lock.json` 锁死 | 需要严格复现、跨机比对结果、CI |
| **system** 复用系统安装 | `cyctl start --engine system` | 0 | 中：版本取决于用户装了什么 | 本机已有 Cytoscape；磁盘紧张 |
| **attach** 接管运行中的实例 | `cyctl start --engine attach` | 0 | 取决于该实例 | 桌面用户手工开着 Cytoscape，想让 Agent 直接接管 |

默认 `--engine auto`：**有自带就用自带，没有则回落系统安装**。

> ⚠️ **system / attach 模式的确定性代价**：结果随该安装的版本与已加载 App 变化。
> 用这两种模式跑出的任何结论，都必须把**实际引擎版本**记进溯源清单再对外报。
> `cyctl run` 产出的 manifest 里 `engine.info` 就是这个用途 —— 跨机比对前先核对它。

`cyctl discover` 会扫这些位置：

- **Windows**：`Program Files`、`Program Files (x86)`、`%LOCALAPPDATA%\Programs`、scoop、chocolatey
- **macOS**：`/Applications`、`~/Applications`、`/opt`、`/Library/Java/JavaVirtualMachines`、Homebrew
- **Linux**：`/opt`、`/usr/local`、`/usr/share`、`/snap`、`/usr/lib/jvm`、SDKMAN、`$HOME`

扫描是「先按名字过滤顶层目录、再做有深度上限的遍历」，避免递归整个 `Program Files`（那会耗时以分钟计）。

## 3. 宿主矩阵

九类宿主，三种接入通道（详见 `docs/03`）：

| 宿主 | 传输 | 通道 | 配置字段 |
|---|---|---|---|
| Claude Code | Streamable HTTP | 1 | `mcpServers` + `type:"http"` + `url` |
| VS Code / GitHub Copilot | Streamable HTTP | 1 | **`servers`** + `type:"http"` + `url` |
| GitHub Copilot CLI | Streamable HTTP | 1 | `mcpServers` + `type:"http"` + `url` |
| OpenAI Codex CLI | Streamable HTTP | 1 | TOML `[mcp_servers.<id>]` + `url` |
| Cursor | Streamable HTTP | 1 | `mcpServers` + `url`（无 `type`） |
| Gemini CLI | Streamable HTTP | 1 | `mcpServers` + **`httpUrl`** |
| Windsurf / Cascade / Devin | Streamable HTTP | 1 | `mcpServers` + **`serverUrl`** |
| Claude Desktop | **stdio** | 2（`cyctl bridge`） | `mcpServers` + `command`/`args` |
| 任意自定义客户端 | 任意 | 1 / 2 / 3 | 见 `cyctl mcp` 输出 |

```bash
cyctl mcp                              # 全部九类
cyctl mcp --host cursor,gemini-cli     # 指定
```

## 4. 真正的天花板（诚实清单）

### 4.1 手工 GUI 交互没有脚本接口

拖拽节点、框选、边拖边看的实时预览 —— 这些本质是 GUI 交互，CyREST / Commands API
都没有对应接口。它们也不产生「结果」，谈不上「结果一致」。

### 4.2 官方没发布的产物就是没有

- Windows ARM64、Linux ARM64 的 Cytoscape 官方**没有**分发；
- 官方 JRE 只覆盖 macOS 与 Windows；
- 官方 sha256 清单只覆盖 4 个安装包。

这些不是本技能的缺口，是上游的事实。覆盖方式一律是 **`--engine system`**，
而不是「假装能下载」。

### 4.3 随机性不等于不确定（详见 `docs/02`）

力导向类布局默认带随机种子。可复现的是**拓扑、属性、表数据**，不是节点像素坐标。
需要逐像素一致时必须固定种子并记录 —— 这在 `docs/02` §2.1 有完整清单。

## 5. 一键体检

```bash
cyctl doctor
```

输出每一项的 `ok` / `level` / `detail` / `fix`，并按 `level=error` 汇总成 `blocking_ids`。
退出码：全部关键项通过 → `0`；有阻断项 → `3`。

覆盖的检查项：Python 版本、版本锁定文件、Java 17、Cytoscape 引擎、CyREST 可达性、
MCP App 是否暴露 `/mcp`、代理变量、运行时目录可写、磁盘余量、虚拟显示（Linux）、端口状态。
