## 2. 发现并修复的问题

严重度：**高** = 可导致安全事件或静默错误；**中** = 违反契约或造成误判；**低** = 健壮性缺口。

### 2.1 \[高\] 归档解压无路径穿越防护（Zip Slip / Tar Slip）

- **位置**：`scripts/cyctl.py` → `_extract()`
- **问题**：原实现对 zip 用 `zf.extractall(dest)`、对 tar 用 `tf.extractall(dest)`。
  归档内的条目名由归档自己控制，`../` 或绝对路径可以写到 `dest` 之外；
  符号链接还可指向目录外，在后续写入时逃逸。
- **为何是高危**：`provision` 下载的产物中有 **`sha256: null`** 的（官方未提供哈希），
  下载链路一旦被劫持，未防护的解压等于**任意文件写入**。
- **修复**：新增 `_is_within()`，逐条校验条目路径；符号链接额外校验**链接指向**。
  越界即抛 `ValueError`，由 `cmd_provision` 转为退出码 `5`。
- **回归**：`tests/test_safety.py::TestExtractSafety` 6 个用例（含同级前缀陷阱
  `/a/b` vs `/a/bc`、tar 逃逸、zip 逃逸、绝对路径、符号链接逃逸、正常归档不误伤）。

### 2.2 \[高\] 官方未提供哈希的产物被静默安装

- **位置**：`scripts/cyctl.py` → `cmd_provision()` 原第 326 行
- **问题**：
  ```python
  if spec.get("sha256") and verified is False:   # sha256 为 None 时整条短路
      ...fail...
  # 然后继续 _extract() 解压安装
  ```
  官方 `sha256sums` **只覆盖 4 个安装包**（macOS dmg ×2 / `unix.sh` / `windows.exe`），
  `tar.gz`、`zip` 与官方 JRE 全都没有哈希。原实现在这种情况下 `verified: null`
  却照常解压安装 —— 等于**静默信任一个未校验的二进制**。
- **实测佐证**：本机执行 `provision --component jre` 真的下载了 41.7 MB 并解压安装，
  结果里 `"verified": null`，没有任何阻断。已确认官方 JRE 站
  `cytoscape-builds.ucsd.edu/.../jres/` **不提供** `sha256sums`/`md5sums`（探测返回 404）。
- **修复**：改为 **fail-closed**。`sha256` 为空且无 TOFU 基准匹配时**默认阻断**，
  退出码 `5`，并在结果里回传实测 sha256 供核对；必须显式 `--allow-unverified` 才放行。
  同时在锁定文件新增 `tofu_observed` 字段，记录首次下载实测值，用于**后续下载的一致性比对**。
- **诚实标注**：`tofu_observed` 来自本机一次下载，**未经官方清单交叉验证**，
  它防的是「同一产物被悄悄替换」，不是「首次下载未被污染」。锁定文件里已写明。

### 2.3 \[高\] 退出码 2 时 stdout 为空，违反输出契约

- **位置**：`scripts/cyctl.py` → `build_parser()` / `main()`
- **问题**：argparse 在用法错误时自行向 stderr 打印 usage 后 `sys.exit(2)`，
  **绕过 `emit()`**，stdout 完全为空。契约承诺「stdout 恒为一个 JSON 对象」，
  按契约 `json.loads(stdout)` 的 Agent 会**直接崩溃**。
- **实测复现**（修复前）：`cyctl bogus-subcommand` → stdout 空、退出码 2。
- **修复**：自定义 `ArgParser.error()` 覆盖 argparse 的报错行为，改为输出 JSON；
  `main()` 增加兜底 `except`，任何未预期异常也产出 JSON（traceback 同时写 stderr）。
- **顺带修复**：`--version` 原本向 stdout 打印纯文本 `cyctl 0.1.0`，同样破坏契约，
  改为 `VersionAction` 输出 JSON。
- **回归**：`tests/test_safety.py::TestCliJsonContract` 10 个用例。

### 2.4 \[中\] `--force` 的日志与行为相反

- **位置**：`scripts/cyctl.py` → `cmd_provision()` 原第 308–311 行
- **问题**：
  ```python
  if target.exists() and not args.force:
      log("%s 已存在于 %s（--force 可强制重装）")   # 只打日志，没有 return
  if not archive.exists() or args.force:
      ...重新下载...
  # 然后照样解压覆盖
  ```
  日志暗示「已存在，需 `--force` 才重装」，实际**照样重装**。调用方读到这条日志
  会误判为「已跳过」。
- **修复**：改为真正的幂等 —— 目标已存在且未加 `--force` 时直接返回
  `already_installed: true`，不下载、不解压。
- **回归**：`test_already_installed_is_idempotent`、`test_force_reinstalls_even_if_present`。

### 2.5 \[中\] 下载非原子：中断留下半截文件被当作有效缓存

- **位置**：`scripts/cyctl.py` → `_download()`
- **问题**：直接写目标路径。中断后下次调用命中 `archive.exists()`，
  走「复用已下载归档」分支；对 `sha256: null` 的产物**直接解压半截文件**。
  与 2.2 叠加，后果不可控。
- **修复**：写 `.part` 临时文件，完成并校验后 `os.replace()` 原子改名；
  失败时清理 `.part`。同时校验 `Content-Length` 与实际字节数，提前识别截断。
- **回归**：`TestDownloadStability`（失败后不留 `dest` 与 `.part`、空响应被拒）。

### 2.6 \[中\] 下载无重试，且锁定文件的 `size_mb` 从未被使用

- **问题**：226 MB 的安装包在慢链路上一次超时即整体失败；锁定文件里
  精心记录的 `size_mb` 形同虚设。
- **修复**：加入 3 次重试 + 指数退避；把 `size_mb` 换算为 `expected_size`
  传入，与 `Content-Length` 做前置比对（偏差超 1 MB 即在日志中警告）。

### 2.7 \[中\] 参数解析异常未捕获，导致 traceback + stdout 为空

- **位置**：`cmd_do_rest()`、`cmd_run()`
- **问题**：
  - `dict(p.split("=", 1) for p in args.param)`：`--param foo`（缺 `=`）抛 `ValueError`
  - `json.loads(args.body)`：非法 JSON 抛 `JSONDecodeError`
  - `json.loads(wf_path.read_text())`：非法工作流 JSON 抛 `JSONDecodeError`

  三者都会打出 traceback、`stdout` 为空、退出码 `1` —— 既违反契约，
  又让调用方无法区分「内部错误」与「没有输出」。
- **修复**：全部转为结构化的 `fail(EXIT_USAGE, ...)`，附可读原因。

### 2.8 \[低\] 有期望哈希但校验结论为 `None` 时会静默放行

- **来源**：修正测试 mock 时发现的防御缺口 —— 若 `_download` 因任何原因
  在收到期望哈希的情况下返回 `verified=None`，原逻辑会**跳过**两道校验直接安装。
- **修复**：新增内部一致性断言，遇到此情形即 `fail(EXIT_INTEGRITY)` 并删除下载文件。
  **宁可报错，也绝不放行一个「本该校验却没校验」的产物。**
- **回归**：`test_expected_hash_but_no_verdict_is_rejected`。

### 2.9 \[低\] Python 3.14 的 tar 解压默认行为会改变结果

- **证据**：测试运行中出现官方 DeprecationWarning ——
  「Python 3.14 will, by default, filter extracted tar archives and reject files
  or modify their metadata」。
- **风险**：3.12 起 `tarfile` 引入 `filter` 参数，未来默认值将由 `fully_trusted`
  变为 `data`，会**拒绝符号链接、改写元数据** —— 解压结果随解释器版本漂移，
  这对「确定性」是直接的威胁。
- **修复**：新增 `_tar_extract_member()`，显式传 `filter="fully_trusted"`，
  把确定性的决定权收回自己（安全由我们自己的 `guard()` 提供）。
  旧版本解释器按 `TypeError` 回退。

### 2.10 \[低\] 下载缓存无清理入口

- **问题**：每次 `provision` 都把归档留在 `runtime/_downloads`，
  长期运行会累积数百 MB。
- **修复**：新增 `cyctl prune`，默认 dry-run 只报告体积，`--yes` 才真正删除。

### 2.11 \[提示\] `describe` 能力清单与实际子命令不同步

- **问题**：新增 `prune` 后 `describe` 未列出，自描述与实际不符。
- **修复**：补入清单，并加测试断言 `describe` 输出必须包含 `prune`。

### 2.12 \[记录\] 下载与 CyREST 的代理策略差异已被显式化

- **说明**：`_download` 访问的是**外网**资源，应当走环境代理；
  而 CyREST 永远是**本机**地址，必须绕过代理（本机设了 `http_proxy` 时，
  代理会劫持 `localhost` 请求并返回 502 —— 这是先前已修复的坑）。
  两者行为相反是**正确的**，但原实现未加说明，容易被后人误「统一」。
- **处理**：把 `use_proxy` 参数化并默认开启（含 `--no-proxy` 开关），
  在两处代码与锁定文件的 `proxy_policy` 说明中写明这个区别。
